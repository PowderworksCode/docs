Five things say where you are or take you where you asked; the search box
alone waits for a question.

## The index

The whole tree, all the time, in the body voice: sections bold, the page you
are on underlined, with the site's mark travelling to sit beside it. It is
built at build time, so the highlight is markup rather than something a script
works out on arrival.

## The search box

Above the index, answered by Pagefind from an index built at build time and
fetched only on the first keystroke. Results stand where the tree stood —
titles and excerpts, the match set bold — and clearing the box, or Escape,
puts the tree back. With JavaScript turned off the box never appears, for the
same reason the button never does.

Try it: search for *frontmatter*.

## The button, on a narrow screen

Below 56rem the index and the search box fold behind a button beside the name.
Opening it pushes the page down rather than covering it, so there is no
overlay to trap focus in, nothing to dim, and no scrolling to lock — and it
opens the tree in full, sub-lists included.

Resize this window past the fold and back to watch it happen. With JavaScript
turned off the button never appears and the index sits above the words, top
level only, which is where it always sat.

## Breadcrumbs and the pager

Above the heading: the path, as links. Below the last paragraph: the previous
and next pages in sidebar order, so a reader who wants the whole thing can read
it the way it is arranged.

## What is not here

No version switcher, no sidebar of headings on the right, and no overlay
anywhere: even search results are a list standing where a list stood, not a
layer over the page. A page short enough to read does not need indexing twice.
