## Design Context

### Users

Powderworks documentation is for external developers evaluating, adopting, and using the
individual tools. The documentation should help a user understand what a project does, install
it, and complete real tasks quickly. Contributor workflows are not a current design audience.

### Brand Personality

Warm, industrial, and editorial. The shared Powderworks identity should feel practical and
crafted rather than corporate or generic: useful machinery presented with the character of an
independent workshop.

### Aesthetic Direction

Use the Powderworks website as the family reference: warm paper-toned surfaces, dark mineral
ink, and a molten-orange fleet accent informed by the mill artwork. Documentation sites share
typography, navigation behavior, reading rhythm, and core interaction patterns while each
project develops its own accent colors, marks, illustrations, and imagery. Support light and
dark modes, with WCAG AA contrast required in both.

### Design Principles

1. Optimize first for users trying to understand and use the software.
2. Establish family resemblance through structure and craft, not identical project skins.
3. Keep long-form technical reading calm, legible, and editorially paced.
4. Let each project express its identity through constrained theme extension points.
5. Treat accessibility, responsive behavior, and reduced motion as theme requirements.
